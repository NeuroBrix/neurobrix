# The catalogue table — one model, one name

`catalogue.tsv` is the one table of the catalogue's 49 models (the owner's rule, 2026-10-24): one line per model,
every cell read from an artefact, never typed. Columns:

| column | read from |
|---|---|
| unique name | the exact Hugging Face identifier of the repository the container is built from (HF's answer today at the recorded revision — a renamed organisation answers its new name), or the vendor's repository for weights released outside Hugging Face; a repository that carries several weights names the model `<repository>:<the vendor's weight file>` |
| cache entry | the container's folder in the shared cache (`~/.neurobrix/cache/<entry>/manifest.json`) |
| hf_snapshots folder | the snapshot folder the cache entry resolves to (`->` a symlink's target) |
| NAS path | `models/<category>/<folder>/model.nbx`, the served container |
| hub slug | the hub's own listing (`/api/models`) |
| weights sha256 | the LFS sha256 Hugging Face serves for each weight file at the recorded revision, digested as the sha256 of the sorted `"<file> <sha256>"` lines; the vendor's single file's sha256 where one file is the model; the local files' digest, same formula, where no revision is recorded (`catalogue.sources.tsv` says which) |
| container sha256 | sha256 of the NAS `model.nbx` |

A duplicate — the same weights under two names — is forbidden; each upscaler per factor is a model of its own (their
weights differ). Every tool that needs a model's name reads this table. It is regenerated by
`tools/catalogue_table.py` (to come with the rename lot) and never edited by hand.
