# The catalogue table — one model, one name

`catalogue.tsv` is the one table of the catalogue's 49 models (the owner's rule, 2026-10-24): one line per model,
every cell read from an artefact, never typed (public columns, 2026-10-24):

| column | read from |
|---|---|
| repository | the Hugging Face identifier of the repository the container is built from (HF's answer today at the recorded revision — a renamed organisation answers its new name), or the vendor's repository for a weight released outside Hugging Face |
| unique name | the repository; `<repository>:<weight file>` when one repository holds several models (SwinIR, Real-ESRGAN) |
| hub slug | the hub's own listing (`/api/models`) |
| HF revision | the commit the container's manifest records; a container built before revisions were recorded says so and names HF's `main` on the day the table was built |
| weights sha256 | the LFS sha256 Hugging Face serves for each weight file at the revision, digested as the sha256 of the sorted `"<file> <sha256>"` lines; the vendor's single file's sha256 when the weight is released outside Hugging Face; verified against the local snapshot file by file (`verify_snapshots`) |
| container sha256 | sha256 of the served `model.nbx` |

The table holds no local path: where a machine keeps its snapshots, its cache entries and its served containers is that
machine's own record (the full table, with those columns, lives in its private `docs/internal/catalogue.tsv` and a dated
copy in its registers).

A duplicate — the same weights under two names — is forbidden; each upscaler per factor is a model of its own (their
weights differ). Every tool that needs a model's name reads this table. It is regenerated by
`tools/catalogue_table.py` (to come with the rename lot) and never edited by hand.
